# 有限表による PEG の有界認識

`lean/Shallot/Peg/Packrat/` は、停止性を仮定しない任意の PEG について、
固定した入力での成功・失敗・導出なしを有限回の表計算で区別する。
固定した二文字で表すビット入力について、実際の TM による一様な多項式上界まで
接続した。固定二進アルファベット上の `PEL ⊊ P` は
[対角線の証明](peg-strict-in-p.md) へ接続済み。

## 表と意味論

各セルは式と入力位置の組で、値は次の三種類。

| 値 | 意味 |
|---|---|
| `none` | まだ値がない。反復が安定した後は、導出が存在しない |
| `some none` | 意味論上の失敗 |
| `some (some k)` | `k` 文字を消費して成功 |

`F` は前の表を参照して一段を計算する。空の表からの反復を `iter` とする。
`iter_eq_run` は、各反復が同じ深さの燃料付きインタプリタ `pegRun` の結果から
構文木を除去したものと一致することを示す。これにより、既存の `Derives` に対する
健全性・完全性を再利用する。成功後の位置が入力の範囲内にあることも証明する。

## 有限回での安定

`dom g` は開始呼出しと全規則の部分式のリスト。入力末尾を含めた全位置との組を
`cells g x` とすると、その長さは `(dom g).length * (x.length + 1)`。
リストに同じ式が重複していてもよい。

一度埋まったセルの値は変わらない (`iter_mono`)。
関連セル全体で連続する二つの表が一致すれば、その後も一致する (`agree_step`,
`agree_later`)。関連セルは依存先について閉じており、成功した消費量は入力を
越えないため、範囲外のセルを使う必要がない。

安定していない各反復では少なくとも一つセルが新しく埋まる。
埋まったセル数は `cells` の長さを越えないので、
`bound g x = (dom g).length * (x.length + 1) + 1` までに安定する
(`bound_stationary`, `bound_fixed`)。

`bounded_iff` はこの時点の値と導出の存在の同値、`bounded_none_iff` は空セルと
導出の不存在の同値。開始規則では `parse_iff` / `parse_none_iff` に特殊化する。
`accepts_iff` は入力の残りを許す Ford の受理条件 `Shallot.Accepts` との一致。
`fullAccepts_iff` は入力を全部消費する場合の同値で、`Cfg.IsPEL` の受理条件に対応する。
文法全体の全入力での停止性を判定する定理ではない。

## 保存する実装

関数としての `iter` は仕様であり、参照のたびに再計算が起こり得る。
その反復回数だけから実行時間は結論できない。

`Stored.lean` は関連セルの値を連想リストへ保存する。`stored` の各反復は、
直前の保存済み表を `fetch` で参照し、次の表を `save` で作る。
`stored_eq_iter` で仕様との一致を証明し、`storedParse_iff` と
`storedParse_none_iff` で具体的な有限表実装を元の意味論へ接続する。

## 具体的なスタック機械のセル

`Machine/Code.lean` は成功時の消費量を絶対的な到達位置へ符号化する。
未知は `0`、失敗は `1`、位置 `j` で終わる成功は `j + 2`。
`step_encode` はこの数値表の一段と元の `F` の一致。
成功位置は開始位置以上かつ入力末尾以下に収まる。入力長 `N` の行は
`N + 1` 個の数を持ち、各値は `N + 2` 以下。
`start_full_iff` は開始位置の最終値が `N + 2` であることと、
入力を全部消費する導出の存在の同値。

`Machine/Read.lean` は既存の `Complexity.peekAt` を呼ぶ具体的な `NProg`。
行と位置を保ち、作業スタックを戻し、出力スタックへ値を一つだけ追加する。
次の4種類も具体的なプログラムで、結果・変更されるスタック・上限を
`NRuns`（`NExec` の存在とステップ数）として証明した。

| セル | ファイル | 検証済みの行に対するスタック機械のステップ上限 |
|---|---|---|
| 連接 | `Machine/Seq.lean` | `20 * N + 47` |
| 順序付き選択 | `Machine/Alt.lean` | `20 * N + 34` |
| 反復 | `Machine/Star.lean` | `20 * N + 57` |
| 否定先読み | `Machine/Not.lean` | `10 * N + 20` |

4本の `nruns_*Cell_round` は、前の反復の行を仮定すると次の反復の値を
出力することを示す。機械の実行や一致を前提として受け取る定理ではない。
入力の任意位置（末尾も含む）、任意の文法、任意の反復について成り立つ。
連接と反復の成功先は前の反復の行から読むため、機械自身は再帰しない。
反復の補助プログラムは、意味論から証明した「反復は失敗しない」を用いて
元の表へ接続する。初期の空セルや、消費せずに成功する本体も範囲内。

## 文字照合と全構文のコンパイラ

`Machine/Symbol.lean` は入力文字を `c.toNat + 1`、末尾の印を `0` とし、
`inputRow x` に入力順で並べる。NUL 文字の符号は `1` なので末尾と区別できる。
`Test.lean` は有限個の真偽値を具体的な分岐木へコンパイルする。
範囲外の数には固定の既定分岐を使う。実行中に任意の判定関数を呼ぶ仕組みではない。

`Lex.lean` は任意文字・文字・文字範囲をこの分岐と入力行の読み出しで計算する。
`nruns_lexCell_input` の上限は `10 * N + 2 * flags.length + 20`。
`flags` の長さは照合する文字や範囲から決まる定数。
`Literal.lean` は文字列を固定の照合列に展開し、専用カーソルを使う。
`nruns_literalCell` はカーソルを戻し、出力以外を保存して元のリテラル規則と
同じ値を返す具体的な実行。`literalCost_le` により、固定リテラルでは入力長に線形。
空文字列、入力途中での不一致、入力不足も同じ定理で扱う。

`Layout.lean` は文法ごとに `8 + 2 * (dom g).length` 本のスタックを割り当てる。
8 本は入力・長さ・位置・作業領域・カウンタ、残りは旧行と次行。
式の参照は `dom` の最初の出現へ向け、重複した出現にも別々の行を割り当てる。
これらの領域が互いに衝突しないことも証明する。

`Cell.lean` の `compileCell` は全ての `PExp` の形を具体的な `NProg` へ変換する。
非終端呼出しでは実際に対応する旧行を読み、規則欠落なら失敗を返す。
`nruns_compileCell` は任意の文法・式・反復・入力位置で、次の反復の値を
指定した次行だけへ追加し、他の全スタックを保存することを示す。
上限は `cellCoeff e * (N + 1)`。旧行の内容と入力行を前提とするが、
セルの実行や意味論との一致を前提として受け取る定理ではない。

## 行と表全体の走査

`Row.lean` の `fillRow` は位置 `0` から `N`（末尾）まで、セルをカウンタ付き
ループで計算する。`nruns_fillRow` は次行にちょうど元の表の次ラウンドの行が
追加されること、他の全スタックと位置・カウンタが元へ戻ることを示す。
上限は `(N + 1) * (cellCoeff e * (N + 1) + 3) + 6`。

`Sweep.lean` の `sweep` は `dom` の全出現について行プログラムを順に実行する。
`nruns_sweep` は、次行が空なら全ての次行が元の表の次ラウンドと一致し、
旧行を含む他の領域が保存されることを示す。部分式の重複も許す。
`sweepCost_le` は一走査の上限を文法ごとの定数 × `(N + 1)^2` に抑える。

## 初期化・全反復・停止

`Transfer.lean` は旧行を空にし、次行を空の作業スタック経由で移すことで、
順序を保って置き換える。次行と作業スタックは空へ戻る。
`Round.lean` の `Ready` は全ての旧行が指定ラウンドと一致し、次行が空であり、
入力行と長さが保存されていること。`nruns_roundP` は走査＋転送により
`Ready n` を `Ready (n + 1)` へ進める具体的な実行を与える。

`Iterate.lean` は入力長と固定の部分式数から実際に `bound g x` を計算し、
カウンタ付きループでその回数だけラウンドを実行する。
外側のカウンタはリテラル用カーソルの下に保持する。各リテラルの処理が
元のスタック内容を戻すため、外側の制御に干渉しない。
`nruns_iterateBound` が全反復をつなぎ、`iterateCost_le` が三次の上限を示す。

`Input.lean` は `Complexity.nInit` の実際のビット入力を消費して、
固定関数 `f : Bool → Char` で表す文字列 `w.map f` の入力行と長さを作る。
`Initialize.lean` は全ての旧行に末尾を含む位置数だけゼロを入れ、`Ready 0` を作る。
`Finish.lean` は開始規則の旧行の位置ゼロを読み、入力長＋2と比較して停止する。
未知・失敗・部分消費は拒否、全消費だけが受理となる。

`Main.lean` の `program g f` はこれらを全てつなぐ。
`program_halts` は準備済みの表や機械の実行を前提に取らず、`nInit` から停止する実行と、
その答えが `∃ t, Derives g (.nt g.start) (w.map f) (.ok t [])` と一致することを示す。
`program_halts_fullAccepts` は既存の有界認識器との一致。
`programCost_le` は文法と二文字に依存する定数 × `(w.length + 1)^3` の上限。

## 具体的な TM 上の一様な上界

`TM.lean` は既存の検証済み変換 `nprog_lexec` と `lm_time` を実際の
`program g f` に適用する。数のスタックの空間は時間からの一般補題
`nexec_space` で抑える。これにより、空間上限を別の仮定に置く必要はない。

`program_tm` は `TM (NK g + 1)` の判定機械と明示的な停止期限を与える。
`tmTime_degree15` がその期限を定数 × `(N + 1)^15` に抑え、
`bitLanguage_time15` は、任意の文法 `g` と固定した `f : Bool → Char` に対し、
`w.map f` を全消費して受理するビット言語を、その期限内で判定する具体的な TM の存在。
係数は文法と二文字に依存するが、次数 **15 は全ての文法に共通**。

`Shallot/Peg/Separation/` で、この一様な次数を使った多項式時間の対角言語
`PolyDiag 15` を構成し、固定二進アルファベット上の `PEL ⊊ P` を証明した。
既存の文字列版 `Cfg.IsPEL` に属さない反例にも接続済み。
[定義の対応と分離の証明](peg-strict-in-p.md) を参照。

## 検証

`Examples.lean` は左再帰、空文字の反復、先行枝の発散で後続枝へ進めない選択、
先行枝の成功で発散する後続枝を呼ばない選択、規則欠落、文字不一致、
リテラルの部分消費、貪欲な反復をカーネルで検証する。
左再帰と空文字反復に関しては導出の不存在も定理へ接続している。
同じリテラルに対し、入力を全部消費する場合と接尾辞を残す場合の
`fullAccepts` の違いも検証する。
主要な定理の標準的依存のみを `lean/Audit.lean` のメッセージ検査で固定する。

`Machine/Examples.lean` は NUL と末尾、照合表の範囲外の Unicode 文字、
逆順の文字範囲、リテラルの成功・途中不一致・入力不足・末尾での空照合を検証する。

`Machine/EndToEnd.lean` は完全なプログラムの定理を、リテラル受理、接尾辞を残す拒否、
先行枝の発散による拒否、先行枝の空成功による受理へ適用する。
実際の `nInit` からの停止証明であり、準備済みの表からのテストではない。
